# 顺路捎 · 行李额互助小程序

同路人行李额互助工具：有空余行李额的人发布行程，需要捎带的人报名，双方线下自行沟通与交接。**不接线上支付、不做货运撮合、不代收费用。**

> 🟢 **零配置先跑起来**：项目默认开启**演示模式**（`miniprogram/config.js` 里 `USE_MOCK: true`），用本机数据模拟全部 8 个云函数，**不用开通云开发、不用部署、不用环境 ID**，导入 → 编译 → 扫码即可真机跑通全流程。见《免费试跑清单.md》开头。
> 🚀 **之后要真实多人互通**：照《免费试跑清单.md》六步走；**正式上架**看《上线操作手册.md》。

## 一、快速开始（3 步跑起来）

1. **导入项目**：打开微信开发者工具 → 导入项目 → 目录选 `lugshare` 这一层。
2. **填 AppID**：新手可选"测试号"，或填自己的 AppID；项目配置里 `appid` 当前为占位的 `touristappid`。
3. **开通云开发**：点开发者工具顶部「云开发」→ 开通 → 记下环境 ID（如需要多环境，填入 `miniprogram/app.js` 里的 `envId`，单环境可留空用默认）。

然后创建数据库集合 + 部署云函数（见下），即可编译预览。详细步骤见《免费试跑清单.md》。

## 二、数据库集合（3 个）

在云开发控制台 → 数据库，新建以下集合：

| 集合名 | 用途 | 建议索引 |
|---|---|---|
| `users` | 用户 | `openid`（唯一） |
| `trips` | 行程 | `status`+`departDate` 组合；`openid` |
| `demands` | 报名需求 | `tripId`；`openid` |
| `chat_conversations` | 会话 | `convId`（唯一）；`participants`+`updatedAt` |
| `chat_messages` | 聊天消息 | `convId`+`createdAt` |
| `chat_read_state` | 已读状态 | `openid`+`convId` |

> 权限建议：六个集合都设为「仅管理端可读写」（云函数用管理端权限操作），前端不直接读写数据库，全部走云函数。

## 三、部署云函数

`cloudfunctions/` 下有 8 个云函数：
- 基础：`login`、`trip`、`demand`
- 聊天：`chatSend`、`chatConversations`、`chatMessages`、`chatReadMark`
- 订阅消息：`subscribeNotify`

在开发者工具里对每个云函数右键 →「上传并部署：云端安装依赖」，等全部部署完再预览。

### 订阅消息配置（可选，不配也能正常用，只是没有离线提醒）

订阅消息需要手动申请模板并配置 ID，共 2 步：

1. **申请模板**：微信公众平台 → 功能 → 订阅消息 → 公共模板库，申请 3 个模板（选字段结构相近的即可），记下模板 ID：
   - 收到新报名：字段建议 ` thing1=行程 / time2=日期 / thing3=说明 `
   - 报名结果：字段建议 ` thing1=结果 / thing2=行程 / time3=日期 `
   - 收到新消息：字段建议 ` thing1=发送人 / thing2=内容 / time3=时间 `
2. **填模板 ID**：
   - 前端：`miniprogram/utils/subscribe-tmpl.js` 里的 `TMPL.NEW_APPLY / APPLY_RESULT / NEW_MESSAGE`
   - 云端：`subscribeNotify` 云函数的环境变量 `TMPL_NEW_APPLY / TMPL_APPLY_RESULT / TMPL_NEW_MESSAGE`
   - 两处必须填一样的 ID。**模板字段的关键词（thing1/time2 等）要与云函数 `sendRaw` 里 data 的 key 一致**，否则发送失败。

> 调试时把云函数环境变量 `MP_STATE` 设为 `trial`（体验版）或 `developer`（开发版）；上线改回 `formal`。
> 一次性订阅：用户授权一次只能收到一条提醒，代码已在报名、发消息、处理需求等关键动作引导授权。推送失败一律静默降级，不影响主流程。
> 官方文档：https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html

## 四、页面与流程

| 页面 | 功能 |
|---|---|
| 首页（大厅） | 按出发/到达城市、日期筛选行程，下拉刷新、上拉分页 |
| 发布 | 带货人发布行程，强制勾选合规承诺 + 违禁词本地校验 |
| 详情 | 求带人报名；带货人管理需求状态（确认/拒绝/寄出/在途/送达），额度自动增减 |
| 行程 | 我发布的 / 我参与的 双列表 |
| 消息 | 会话列表，未读红点 |
| 聊天 | 文字聊天，轮询更新 + 乐观发送 + 已读标记 |
| 我的 | 称呼设置、合规须知 |

**核心状态机（防超卖）**：报名时用云端事务校验剩余额度并占用 `usedKg`；拒绝/撤回时事务释放额度；送达时按实际重量校准。

**站内聊天（不暴露隐私联系方式）**：会话 ID 由「行程 ID + 双方 openid 排序」确定性生成，双方落在同一会话；仅行程相关用户（带货人或非拒绝/撤回状态的报名者）可互发；求带人报名成功后弹窗引导发第一条招呼语，带货人在需求卡片点「联系TA」。文字消息经 msgSecCheck 检测，页面顶部提示勿留敏感信息。聊天采用 3 秒轮询（非 WebSocket），失败指数退避，页面隐藏时停止轮询。

**离线提醒（订阅消息）**：3 类通知——收到新报名→带货人、报名结果→求带人、收到新消息→聊天对方。触发点分别位于报名成功、确认/拒绝需求、发消息成功；授权在对应的用户手势中申请。通知全部为旁路调用，云函数未配模板 ID 或用户拒收时自动跳过。

## 五、合规设计（重点）

- 产品定位为**顺路互助工具**，非货运平台、非买卖行李额；
- 发布/报名均需勾选**合规承诺**（不携带违禁品、不用于商业代购/走私、如实申报）；
- 前后端双重**违禁词校验** + 微信内容安全 `msgSecCheck`（trip/demand 云函数已接入，未开通时自动降级为本地词库，不阻断用户）；
- **不接线上支付**，费用线下自行结清，小程序不代收代付；
- 不采集位置、手机号等隐私接口，头像昵称由用户主动填写，降低隐私协议依赖。

> ⚠️ 微信平台规则、海关与航司规定会更新，提审前请以微信官方最新规范及各航司/海关最新规定为准。
> msgSecCheck 官方文档：https://developers.weixin.qq.com/miniprogram/dev/api/open-api/sec-check/msgSecCheck.html
